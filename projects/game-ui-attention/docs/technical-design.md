# 技术方案

状态：设计草案；文中的技术选择、指标与运行规则为拟定实现。

## 1. 产品目标与证据边界

建立“截图 → 模型预测 → 区域统计 → 游戏 UI 评审”的可复现工作流，辅助判断关键内容是否突出、装饰是否竞争注意力，以及修改是否改变预测分布。

程序负责数值，Agent 负责语义解释。玩家目标影响评审优先级，不改变基础热图，不给指定按钮人为加权。

模型结果是预测分布，不是真实眼动、实际点击率或可用性结论。第一版不推断时间维度，也不设置主按钮必须达到某个百分比的通用合格线。

## 2. 架构

```text
截图 + 玩家目标 + 区域标注
            |
       校验与预处理
            |
       显著性模型适配器
            |
     概率归一化与区域统计
            |
      原图 + 指标 + 证据
            |
        Agent 语义评审
            |
 HTML 报告 / PNG / JSON / Markdown
```

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| Skill | 组织输入、调用工具、形成评审 | 不计算或虚构数值 |
| Python CLI | 校验、预处理、推理、统计、报告生成 | 不直接修改设计稿或项目资产 |
| Backend Adapter | 封装模型初始化与推理 | 必须报告实际模型、权重和配置 |
| AOI 模块 | 矩形/多边形校验、掩码、区域统计 | 不混淆可见图形边界与点击热区 |
| HTML 报告 | 查看原图、热图、区域和比较结果 | 不将展示用颜色当作统计数据 |

第一版以 CLI 为调用边界，不先增加常驻服务。后续按批量使用需求增加进程内模型复用或 MCP；统计逻辑保持共用。

## 3. 技术选型

拟使用 Python、PyTorch、NumPy、Pillow。采用项目独立虚拟环境；在后端跑通后锁定实际兼容的 Python 与依赖版本，不用上游未设上限的依赖声明代替兼容性验证。

| 候选 | 用途 | 当前限制 |
| --- | --- | --- |
| DeepGaze IIE | 静态显著性基线候选 | 代码、权重和依赖许可待明确；游戏 UI 效果未验证 |
| DeepGaze MSDB | 后续模型对比候选 | 需要显示/观看条件，不能从截图猜出 pixels per degree |
| Attention Insight | 可选外部 API/MCP 后端 | 需要账户、额度及明确允许上传的数据范围；结果指标单独映射 |

DeepGaze 官方提供空间 log density 输出及中心偏置输入。参见[来源与选型记录](sources-and-decisions.md)。DeepGaze 尚未定为正式发布依赖；许可未闭合时不打包其代码或权重，先推进独立的统计、报告和后端接口。

GPU 优先；CPU 支持、延迟、峰值内存和显存通过本机实测决定。不得先写“秒级完成”或保证某档显卡能运行。

## 4. 图像处理

1. 校验文件格式、尺寸、方向和可解码性；应用明确的方向与颜色处理规则。
2. 默认要求完整、已合成的 RGB 游戏截图。存在透明度且未给定真实合成背景时拒绝分析，不擅自填黑或白背景。
3. 保留宽高比；使用完整画面，避免分别切块推理破坏全局视觉竞争。
4. 按经验证的模型输入配置缩放；记录原图尺寸、推理尺寸和坐标变换。尺寸超限时明确失败，不静默缩小。
5. 模型输出在有效画面上归一化。需要返回原图尺寸时，对概率图映射后再次归一化。
6. 图片哈希与标注绑定；哈希改变时重新检查区域，不沿用过期位置。

初始不添加局部放大分析。以后若增加，必须标为不同观看条件，结果不能与完整画面混用。

## 5. 中心偏置与观看条件

中心偏置是显式、版本化的分析配置；记录其来源和哈希。不能把 MIT1003 的中心偏置称为游戏玩家的真实习惯，也不能把均匀先验称为已消除模型全部中心偏好。

同一次 A/B 对比必须使用同一先验。可做不同先验的敏感性分析，但应独立展示，不挑选更支持设计建议的一份。

对要求 pixels per degree 的模型，缺少显示尺寸、分辨率及观看距离等必要条件时，不调用该配置或要求补全。固定实验配置可以用于工程比较，但必须标记为实验假设。

## 6. AOI 标注

AOI（Area of Interest）是要比较的视觉区域，例如标题、价格、奖励、主按钮、立绘。使用原图像素坐标，原点为左上角；矩形采用半开边界，具体格式见[接口草案](data-contract.md)。

优先使用人工区域，或具有经过验证的坐标映射的设计节点数据。Agent 自动识别的区域使用 `candidate` 状态并展示边框；相关指标与结论同样标为基于候选边界。

第一版报告支持查看和编辑标注，导出更新后的 JSON；CLI 读取新标注并重算统计，不重新推理。HTML 不隐式写回本地文件或联系外部服务。

允许嵌套和重叠，但指标不可简单求和。父区域使用掩码并集；汇总多个区域时按像素去重。没有可靠区域时允许全图分析，不虚构精确的按钮占比。

## 7. 指标计算

将模型输出 L 转为概率：`P = exp(L - logsumexp(L))`，有效画面上 `sum(P) = 1`。重采样后再次校验有限、非负及归一化。

对区域 R：

| 指标 | 定义 |
| --- | --- |
| probability_mass | `sum(P[R])`，预测注视分布落入区域的质量，范围 0～1 |
| area_fraction | `area(R) / area(image)` |
| relative_density | `probability_mass / area_fraction` |
| delta_pp | `100 * (mass_after - mass_before)`，百分点 |

零面积、越界和自交多边形按输入错误处理。保留浮点原始值，展示舍入不影响计算。

占比 8% 不表示“8% 玩家会看到”，也不表示注视时间占 8%。相对密度较高不自动代表设计更好；其含义取决于区域角色及玩家目标。区域尺寸变化时同时报告面积变化，避免把面积扩大带来的占比增长解释成效率提升。

外部后端如果只返回厂商自有分数或可视化图片，不反推像素概率，不将这些分数冒充本方案指标；通过 capabilities 明确支持范围。

## 8. Agent 评审

输入为原图、区域标签、玩家目标和程序计算的指标。结果按“观察证据 → 目标关系 → 影响推断 → 最小建议”组织。

游戏场景包括奖励结算、商店、装备详情、任务页、弹窗和 HUD。可配置区域角色及预期层级，不使用通用数值阈值。缺少玩家目标时只做描述性评审，或注明采用的目标假设。

每条发现记录证据引用、区域 ID 和证据类型：`computed`（程序计算）、`observed`（画面可见）、`inferred`（影响推断）、`unverified`（缺少验证）。不提供未经校准的模型置信百分比。

严禁从单张截图得出“用户一定看不到”“点击率会提升”“真实注视顺序”等结论。HUD 的运动、场景切换和玩家熟练度属于第一版未覆盖条件。

## 9. A/B 与展示

对比要求模型、权重、预处理、中心偏置、观看配置、指标版本兼容；第一版还要求相同画布尺寸。通过稳定 AOI ID 配对，位置和大小可以改变，但必须提供各自的有效边界。

新增或删除区域单独列出，不编造缺失一侧的 0 值。画面状态、任务或内容明显不同则标为探索性比较，不作修改的因果结论。

PNG 使用固定透明度和可记录的色阶；A/B 共用颜色标尺，不各自拉满红色。统计只读取浮点概率图，不能从 PNG 颜色或额外显示模糊后的图计算。

## 10. 数据、错误和可复现性

缓存以输入图片哈希、后端版本、全部权重哈希、预处理和先验配置为键。语义评审缓存另计玩家目标和 AOI；修改 AOI 不触发模型重跑。

使用推理模式和固定配置；记录设备、计算精度、依赖版本和实际配置。同环境重复结果按规定误差验证，不能无证据保证跨硬件逐位一致。

模型或依赖缺失、权限失败、显存不足、无效输出、配置不兼容均返回结构化错误。禁止静默替换模型、改用云端或生成装饰性热图作为成功结果。

结果写入任务独占运行目录，以 manifest 最后落盘表示计算完成；不覆盖历史报告。Agent 评审失败时保留有效计算结果，报告为部分完成。

本地推理不自动上传截图。当前 Agent 若使用云端视觉模型解释图片，仍可能经过其服务，不能宣称端到端离线。外部 API 路线需要明确的数据上传授权。运行目录、截图与权重默认不纳入 Git。
