# Game UI Attention 分级执行计划

日期：2026-09-11。状态：一级总控下达的执行计划；具体派发与完成状态由实际回执和验收证据决定。

## 1. 目标与指挥关系

一级总控位于 Codex，负责范围、阶段验收、关键技术裁决和公开发布。DHS 二级总控负责日常执行、按需创建子任务会话、划分所有权、收集结果、整合和纠偏。子任务向二级总控汇报，一级总控从二级总控拉取进展。

当前目标：建立可测量的游戏 UI 视觉注意力评估最小工具，先建立评估基准，再选择实际后端；以真实计算、区域统计和证据驱动的解释为产物。

第一版保持静态完整截图、AOI、A/B 和报告范围。任务搜索模型单独研究，不与静态热图混合；动态 HUD、从零训练模型、眼动硬件采购、云服务采购、Unity/Figma 自动操作不属于本轮实施。

## 2. 二级总控的启动顺序

1. 读取本计划、项目 README 和 docs 下现有五份方案文档；确认当前 Git 状态与项目级规则。
2. 建立工作分解、依赖、文件所有权和验收表；识别共享文件，只指定一个写入者。
3. 使用 DHS 原生任务协调能力按需创建子任务。模型路线使用宿主已登记默认值，显式切换时先查真实目录，不猜模型或会话 ID。
4. 串行执行派发请求并核对回执，默认最多三条独立子任务并行；研究任务可以复用会话，不为每个小步骤反复创建。
5. 首次回报应确认工作目录、真实子任务 ID、各任务边界、当前阻塞及下一步；随后继续执行，不因等待一级总控普通确认而停止独立工作。

## 4. 本轮研究增量

现有方案只列 DeepGaze 为主要本地候选，最新研究要求扩充比较：

- UEyes：1,980 张 UI 与 62 名参与者，包含多个观看窗口；有 UMSI++ 实现。普通 UI 数据不能证明游戏预测有效。
- UI 微调 MSI-Net / foveacast-training：优先核实的工程候选；已读取到代码许可和 ONNX 路线，但作者公布的提升尚未由本项目复现。
- DeepGaze IIE/MSDB：保留为通用/适配候选，许可仍需明确；MSDB 观看条件不得猜测。
- SeekUI：截图与文字目标的搜索路径候选；单独实验，不能用任务描述人为重绘静态热图。
- 视觉语言模型用于解释和候选 AOI，不把其猜测注视点当真实标签、眼动真值或评估答案。

## 5. 第二波：串行锁定接口，按模块实现

二级总控汇总第一波，形成后端候选和基准协议，对现有 technical-design、data-contract、implementation-plan、validation-plan、sources-and-decisions 进行串行更新，记录哪些仍为候选。

本计划授权二级总控在本轮范围内完成必要的接口锁定与工程拆分，不要求一级总控逐项批准常规实现细节。模型许可不明确的后端不得打包或使用；此类阻塞不阻止模型无关的统计、报告与评估代码。

后续可按依赖分三条实现线：

- C1：契约、AOI、概率统计、错误语义和评估脚本；共享 schema/config 由二级总控指定唯一负责人。
- C2：已确认可用后端的隔离环境、加载/推理、来源哈希与缓存；不静默下载或替换模型。
- C3：本地报告、区域导出与 A/B 共用色阶；有正式输出契约后开工。

测试与代码由各线在独占目录内配套维护；跨模块整合由二级总控串行处理。实际目录以锁定的工程布局为准，不为并行而引入多套接口。

## 6. 工作区和版本边界

- 基础仓库为 K-Agents-toolbox，本轮允许写入 projects/game-ui-attention/ 内直接相关文档、代码、测试与必要示例；根 README 仅允许更新项目导航和真实状态。
- 此 orchestration-plan.md 由一级总控持有；二级总控需要改变范围时报告建议，不自行覆盖。
- 初始以不重叠文件所有权协作。需要隔离时允许创建专用分支/worktree，必须核实路径和落位，不能覆盖现有目录或迁移用户已有工作。
- 禁止 reset/clean、强推、丢弃已有修改、修改其他项目或桥/宿主实现。
- 可由二级总控集中创建仅含自身范围的本地提交；子任务不得提交整个共享工作区。显式逐文件暂存，不使用 git add -A。
- 本轮子任务和二级总控不 push、不发 Release、不改公开仓库设置；由一级总控验收后统一处理。
- 会话 ID、派发回执、机器路径、原始日志存仓库外协调记录，不写进公开项目文档。公开文档用任务代号和脱敏结果。

## 7. 环境与资源边界

可以在本项目专用环境中安装必要开发依赖，缓存与生成物使用忽略目录或仓库外独占目录，禁止更改全局 Python、系统配置和现有服务。

公开模型/数据下载前先明确来源、体量、许可、用途与存放位置；小规模获准素材和明确许可模型可按计划使用。对于多 GB 数据、长时间训练或资源竞争，先给一级总控资源估计，继续其他独立任务，不自行启动无界任务。

不采购、不创建付费账户、不读取或输出凭据、不上传内部图片、不自动切换云端。模型失败须输出结构化错误，不能用合成热图冒充模型结果。

## 8. 阶段验收

| 阶段 | 验收重点 |
| --- | --- |
| G0 研究收敛 | 候选/许可/环境/基准证据闭合；无自采数据的限制明确 |
| G1 工程闭环 | CLI 成功/错误分支、概率与坐标正确；截图到报告实际跑通 |
| G2 比较可信 | 固定测试划分、同窗口同预处理、中心基线、逐图指标和分组误差；未复现的作者分数不得当本项目结果 |
| G3 工具交付 | AOI 重算、A/B 共用色阶、真实模型与依赖哈希、Skill 原创封装及使用说明 |

真实眼动准确性与软件功能分别验收；缺少游戏眼动数据时只能说明公开数据效果或工程可运行，不能宣称游戏 UI 预测已经准确。

二级总控自主等待、检查和纠偏其子任务；普通里程碑回报后继续范围内工作。许可、任务范围、数据权限、资源预算或发布边界无法解决时报告一级总控，不自行扩权。
