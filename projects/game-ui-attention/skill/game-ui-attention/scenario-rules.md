# 最小场景规则：五类界面的区域角色与预期层级

> **性质声明：本文件全部内容为设计经验规则，非验证结论。**
> 它们只用于：① 构造 AOI 时给 `role` 命名；② 组织评审优先级（先查什么、后查什么）。
> 它们**不是**数值阈值、不是合格线、不改变热图、不给任何区域加权，也不能作为"该界面通过/不通过"的判据。
> 工具对游戏 UI 的预测有效性未验证（无眼动数据）；违反某条经验规则只构成"值得人工复核的发现"，不构成缺陷结论。
> 画面类型不在下表内（如 HUD、加载页、大世界）时，按用户描述的目标自行组织角色，不套用本表。HUD 的运动与场景切换属第一版未覆盖条件。

## 通用约定

- `role` 为自由字符串；建议从下列词表取值，保持同一项目内一致，A/B 对比时同一逻辑区域用同一 `id` 与 `role`。
- 通用角色词表：`title`（标题）、`primary-action`（主行动按钮）、`secondary-action`（次行动）、`close`（关闭/返回）、`reward-content`（奖励内容）、`price-info`(价格)、`item-info`（物品/装备信息）、`quest-info`（任务信息）、`navigation`（页签/导航）、`character-art`（立绘/角色图）、`decoration`（装饰/边框/特效）、`status-info`（状态数值）。
- "预期层级"一律是**定性排序建议**（谁通常应比谁更优先获得注意力），评审时与 `analysis.json` 实测数值对照；对照不符时按 Skill 红线表述（预测分布中的相对关系），并给最小建议。
- 立绘/角色图吸引注意力**不一定是问题**：先对照玩家目标与界面用途判断是"预期卖点"还是"干扰项"，不得机械判错。

## 1. 奖励结算（screen_type 建议：`reward-summary`）

界面目标：让玩家看清获得了什么，并顺利找到领取/确认入口。

| 常见区域 | 建议 role | 说明 |
| --- | --- | --- |
| 结算标题 | `title` | 告知"这是什么结算" |
| 奖励物品列表/图标 | `reward-content` | 界面核心内容 |
| 领取/确认按钮 | `primary-action` | 主出口 |
| 再次挑战/分享等 | `secondary-action` | 次出口 |
| 关闭按钮 | `close` | 逃逸出口 |
| 庆祝特效/边框/背景 | `decoration` | 氛围件 |

预期层级（经验）：`reward-content` 与 `primary-action` 通常应处于最高视觉优先层；`decoration` 不应压过二者。评审重点：装饰特效（放射线、高光、粒子残留）是否与奖励内容竞争同一视觉通道；领取按钮是否与奖励内容形成清晰的"看完→领取"路径。注意：庆祝感本身是此类界面的合法诉求，装饰占比高不自动等于设计错误，需结合玩家目标判断。

## 2. 商店（`shop`）

界面目标：让玩家比较商品与价格，做出购买决策，找到购买入口。

| 常见区域 | 建议 role | 说明 |
| --- | --- | --- |
| 商品陈列格/列表 | `item-info` | 决策主体 |
| 价格/货币栏 | `price-info` | 决策关键信息 |
| 购买按钮 | `primary-action` | 主出口 |
| 页签（道具/装备/礼包等） | `navigation` | 分流 |
| 货币余额 | `status-info` | 购买力提示 |
| 促销角标/限时特效 | `decoration` | 运营件 |

预期层级（经验）：当前选中商品的 `item-info` 与 `price-info` 应共同构成注意力核心；`primary-action` 应与二者邻近且可被顺畅发现。评审重点：促销角标是否喧宾夺主，把注意力从"商品与价格"拉向"运营信息"；多商品并列时，注意力是否被单一格子垄断到影响比较（结合玩家目标判断是否为预期的主推位设计）。

## 3. 装备详情（`equipment-detail`）

界面目标：让玩家读懂这件装备的属性与变化，决定穿戴/强化/分解。

| 常见区域 | 建议 role | 说明 |
| --- | --- | --- |
| 装备图标/模型 | `item-info` | 对象本体 |
| 属性数值区 | `item-info` 或 `status-info` | 决策依据 |
| 对比差值（换装前后） | `status-info` | 变化信息 |
| 穿戴/强化按钮 | `primary-action` | 主出口 |
| 分解/替换等 | `secondary-action` | 危险/次要操作 |
| 品质底框/光效 | `decoration` | 品质表达 |

预期层级（经验）：属性与对比信息通常应优先于品质光效被注意到；`primary-action` 与危险操作（分解）之间应有可辨识的视觉区分。评审重点：品质边框/光效是否遮盖属性可读区；强化入口是否与属性区脱节；危险操作是否与主操作过近（此项属交互惯例推断，标 `inferred`，实际误触风险未验证）。

## 4. 任务页（`quest`）

界面目标：让玩家快速理解"做什么、去哪做、拿了什么"，并出发/追踪。

| 常见区域 | 建议 role | 说明 |
| --- | --- | --- |
| 任务标题 | `title` | 任务身份 |
| 任务描述/目标条目 | `quest-info` | 核心内容 |
| 奖励预览 | `reward-content` | 动机信息 |
| 追踪/前往/领取按钮 | `primary-action` | 主出口 |
| 任务列表/分页 | `navigation` | 任务切换 |
| 剧情插图/氛围图 | `character-art` 或 `decoration` | 叙事件 |

预期层级（经验）：任务目标条目通常应优先于奖励预览与插图被注意到（先知道做什么，再关心得什么）；`primary-action`（追踪/前往）应紧随目标信息。评审重点：插图是否把注意力从目标文本上拉走（同样注意：叙事型任务的插图可能是预期卖点，结合玩家目标判断）；多任务列表场景下当前任务与列表项的注意力分配是否符合用户所选任务语境。

## 5. 弹窗（`popup`）

界面目标：在打断玩家的同时，让玩家最快理解"发生了什么"并做出选择。

| 常见区域 | 建议 role | 说明 |
| --- | --- | --- |
| 弹窗标题 | `title` | 打断事由 |
| 正文信息 | `quest-info` / `item-info`（按内容） | 决策依据 |
| 确认按钮 | `primary-action` | 主出口 |
| 取消/关闭 | `close` 或 `secondary-action` | 逃逸出口 |
| 遮罩后的底层界面 | （通常不标注，或标 `decoration`） | 上下文 |

预期层级（经验）：弹窗主体应显著于被遮罩压暗的底层界面——若底层内容仍与弹窗竞争注意力，说明遮罩/对比处理可能不足；`primary-action` 与 `close` 应可快速区分。评审重点：遮罩是否有效压暗底层（此项多可从画面直接观察，标 `observed`）；双按钮弹窗中主次按钮的视觉权重是否与后果严重性匹配（后果判断标 `inferred`）；注意弹窗截图若含透明区域，必须按用户给定的真实背景合成（`--composite-background`），不擅自填黑填白。

## 使用方式（与评审流程的衔接）

1. analyze 前：按本表给区域定 `id`/`label`/`role`，并把玩家目标写进 `player_goal`。
2. 评审时：先对照该界面的"预期层级（经验）"逐条检查实测数值的相对关系，再按"观察证据 → 目标关系 → 影响推断 → 最小建议"输出 finding。
3. 每条与经验规则相关的 finding 都要在 `inference` 或 `validation_needed` 中注明：层级预期来自设计经验规则，非验证结论；实际玩家行为需眼动/可用性测试验证（`unverified`）。
